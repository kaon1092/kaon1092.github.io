Localization 상세 — 무엇을 했고, 왜 실패했고, 어떻게 고쳤나

① RTK-GPS 구성 (2024)

u-blox ZED-F9P 수신기와 NTRIP 클라이언트로 국토지리정보원 기준국 보정신호를 받아 cm급 위치를 확보하고, 이를 UTM-K 좌표로 변환해 전 노드가 공유하는 절대 좌표계를 만들었습니다. 미션 모드 전환(mode_kcity)이 이 UTM-K 좌표 근접 판정으로 동작하므로, 측위 품질이 곧 미션 성공률이었습니다.

② IMU 칼만 필터 적용 시도 (2024) — 실패에서 배운 것

IMU 자세 안정화를 위해 6-상태 칼만 필터([roll, pitch, yaw, 각속도 3축])를 직접 구성해 적용을 시도했습니다:

class KalmanFilter:
    def __init__(self):
        self.x = np.zeros(6)          # [roll, pitch, yaw, v_roll, v_pitch, v_yaw]
        self.F = np.eye(6)            # 상태 전이: 각도 ← 각도 + 각속도·dt
        self.H = ...                  # 측정: IMU가 주는 roll/pitch/yaw만 관측
        self.R = np.eye(3) * 0.1      # 측정 노이즈 (임의 상수)
        self.Q = np.eye(6) * 0.01     # 프로세스 노이즈 (임의 상수)

    def predict(self, dt):
        self.F[0,3] = self.F[1,4] = self.F[2,5] = dt
        self.x = self.F @ self.x
        self.P = self.F @ self.P @ self.F.T + self.Q

    def update(self, z):              # 칼만 이득 → 상태·공분산 보정
        S = self.H @ self.P @ self.H.T + self.R
        K = self.P @ self.H.T @ np.linalg.inv(S)
        self.x = self.x + K @ (z - self.H @ self.x)
        self.P = (np.eye(6) - K @ self.H) @ self.P

    # 콜백: /handsfree/imu 구독 → predict(dt=0.1 고정) → update → /filtered_imu 발행
실패 원인 분석 (당시에는 몰랐고, 지금은 설명할 수 있는 것들)
  1. 쿼터니언을 오일러각으로 오독 — orientation의 x, y, z 성분을 roll/pitch/yaw로 직접 사용. 쿼터니언→오일러 변환 없이 필터에 넣었으니 수학적으로 성립하지 않는 상태였습니다.
  2. dt = 0.1s 고정 가정 — 실제 IMU 콜백 주기(100Hz+)와 불일치. 센서 간 샘플링 주기 차이를 무시한 채 예측 단계가 돌았습니다.
  3. 공분산(R, Q)을 임의 상수로 설정 — 센서 노이즈 특성을 측정하지 않고 넣은 값이라 칼만 이득이 의미를 갖지 못했습니다.
  4. GPS·휠 오도메트리와의 융합 부재 — IMU 단독 필터라 자세만 다듬을 뿐, 정작 필요한 위치 추정 개선에 기여하지 못했습니다.

③ 2025 — robot_localization 기반 Dual EKF 재설계 (팀장)

위 실패 원인 4가지가 그대로 2025 설계 요구사항이 되었습니다:

2024 실패 원인2025 해결
쿼터니언 오독검증된 robot_localization 패키지 채택 — 자세 표현·변환을 프레임워크에 위임
dt 고정 가정메시지 타임스탬프 기반 시간 동기화 — IMU(100Hz+)·GPS(1–10Hz)·엔코더(10–100Hz) 비동기 융합
공분산 임의 설정센서별 공분산 행렬 측정·튜닝 — 신뢰도에 비례한 가중 융합
단일 센서 필터Dual EKF 구조 — EKF Local(IMU+휠 오도메트리 → 연속 측위) + EKF Global(+GPS, navsat_transform → 절대 측위)

이 구조로 GPS 순간 불안정 구간에서도 측위 연속성을 확보했고, Decision 팀의 Pure Pursuit 경로 추종과 주차 경로 생성이 안정적으로 동작하는 기반이 되어 본선 진출로 이어졌습니다. 연구 내용은 2025 한국자동차공학회 추계학술대회 포스터(1저자)로 발표했습니다.

① odom_encoder — Ackermann 보정 휠 오도메트리 (담당)

# 엔코더 펄스 → 좌륜 이동거리 → Ackermann 기하로 차량 중심 거리 보정
wheel_rotations = delta_pulses / self.encoder_resolution
left_dist = 2π · wheel_radius · wheel_rotations · correction_k   # 실측 보정계수 k

turning_radius = wheel_base / tan(steer_angle)                   # 조향각 기반 선회 반경
center_dist = left_dist · R / (R - wheel_tread/2)                # 좌륜→중심 환산

# 자전거 모델 원호 적분 (직진/선회 분기)
dθ = v/R · dt;  dx = R(sin(θ+dθ) - sinθ);  dy = R(-cos(θ+dθ) + cosθ)

odom.pose.covariance = [0.02, ..., 0.2]   # 공분산 명시 → robot_localization EKF 입력
  • 2024 대비 개선 ① — dt를 고정값이 아닌 메시지 수신 시각 차이로 실측 (rospy.Time 기반)
  • 개선 ② — 공분산을 임의값이 아니라 EKF 입력 규격에 맞게 명시하여 융합 가중치가 의미를 갖도록 설계
  • 개선 ③ — 바퀴 반경·조향 한계·거리 보정계수를 calibration_result.txt로 분리해 대회 당일 재측정 값으로 교체 가능한 구조 (E-stop 초기 오프셋 이슈까지 주석으로 문서화)

② gps_odom_tf — Dual EKF 출력·GPS 정합 노드 (담당)

# /odometry/filtered_map (Dual EKF 전역 출력) + /ublox_gps/fix (RTK-GPS) 구독
utm_x, utm_y = utm.from_latlon(lat, lon)          # 위경도 → UTM
x, y = utm_x - utm_x0, utm_y - utm_y0             # 경로 CSV 기준 원점 상대좌표

Δθ = yaw_rviz - yaw_odom                          # initialpose 기반 heading 오프셋 1회 보정
yaw_adj = yaw_ekf + Δθ

publish /odometry/adjusted_utm  +  TF(utm → gps_base_link, 20Hz)

EKF의 연속적인 자세(heading)와 RTK-GPS의 절대 위치를 결합해, 전역 경로(UTM CSV)와 같은 좌표계에서 경로 추종이 돌 수 있게 만드는 접합부입니다. 초기 heading 정렬(Δθ)을 1회 보정한 뒤 20Hz로 TF를 유지해 Pure Pursuit가 안정적으로 동작하는 기반이 됐습니다.

③ 평행주차 플래너 — Reeds-Shepp 기반 (595줄 상태기계)

  • 주차 슬롯 인지 마커를 받아 진입점 P1 → P2 → 슬롯 중심의 3단계 목표점을 기하적으로 산출
  • 각 구간을 Reeds-Shepp 곡선(전·후진 조합 최단 경로)으로 계획, 후진 기어·미션 hold 제어 포함
  • 차량 외곽(OBB) 기반 충돌 검사 + footprint offset으로 경로 유효성 검증, 실패 시 재계획 서비스 호출
이 조합(휠 오도메트리 → Dual EKF → GPS 정합 → Pure Pursuit / RS 주차)이 2025 본선 진출의 측위·판단 기반이며, 2026 MORAI 시뮬레이션의 MPC 스택으로 이어집니다.

경로 추종 — Waypoint 조향 제어 노드 (협업 파트)

측위 출력이 실제 주행으로 이어지는 경로 추종 계층입니다. waypoints_move가 경로점(waypoint)을 관리·발행하면, waypoint_car_steering_control(C++)이 현재 자세(GPS heading + IMU 융합) 기준으로 목표 경로점을 차량 좌표계로 변환해 조향각을 만듭니다: 

#define MAX_L_STEER -24            // ERP42 조향 한계 ±24°
#define MAX_R_STEER  24
#define MINIMUM_DISTANCE_WAYPOINT_CONTROL 1.0   // 1m 이내 경로점은 통과 처리
#define ANGLE_LOCK 2               // 오차 2° 이내면 직진 고정 (채터링 방지)

// 핵심: 경로점을 차량(base_link) 좌표계로 변환 → 목표 방위각 계산
waypoint_angle = atan2(waypoint_pos_base_link_y, waypoint_pos_base_link_x);
s_angle.data  = heading_angle_steering_control(RAD2DEG(filtered_waypoint_angle));
  • heading 오차에 대한 P/PD 제어로 조향각 생성, 물리 한계(±24°)로 클램프
  • 오차가 작을 때 조향을 잠그는 angle-lock 데드밴드로 미세 진동(채터링) 억제
  • 경로점 근접 시(1m) 다음 경로점으로 전환 — lookahead 방식의 순차 추종

미션 로직 개요 (Decision 팀 파트)

mode_kcity 노드는 K-City의 미션 구간(우회전, 직진, 유턴, 하이패스, 장애물)마다 측정해 둔 UTM-K 기준점 좌표를 갖고, 차량의 현재 UTM-K 좌표가 기준점 반경(2×2m 등)에 들어오면 해당 미션 모드를 발행합니다. 각 노드는 이 모드에 따라 속도·인지 ROI·회피 동작을 바꿉니다. 측위(제 파트)가 흔들리면 모드 전환 자체가 무너지는 구조라, 측위 품질의 중요성을 체감한 부분입니다. (해당 노드 원작성: 팀 Decision 파트)
